## 生命周期退潮判定重构(15:43)

### 问题
当前退潮(declining)判定太简单，只有2个条件：
1. 前日高潮/加速 → 今日无涨停梯队
2. 跌停>=2只

**缺失**：没有体现"板块达到高点后持续回调"的核心含义

### 修复 (lifecycle.py)
**_check_declining() 重写为5个维度**:
1. **高潮后梯队瓦解**: 前日climax/accelerating → 今日max_board<=1且连板=0 ✅保留
2. **惯性延续**: 前日declining + 继续走弱(无涨停或资金流出或K线下跌) → 继续declining
3. **分化后恶化**: 前日diverging → 跌停>=2 或 资金<-10亿 或 涨停<=1且连板=0
4. **K线破位+资金出逃**: K线breakdown或跌破MA20超3% + 资金流出>10亿(3日累计>-20亿)
5. **批量跌停**: limit_down_count >= 3

### _determine_state优先级调整
- 原来：有涨停→资金流→退潮
- 现在：有涨停→**退潮**(最高优先级负面)→分化→资金流→一日游→休眠
- 核心改动：无涨停时，先检查是否曾经活跃的板块在回调（退潮），再看是否有新启动信号（emerging）

### 同步更新
- lifecycle.py 文件头注释

## K线采集性能实测

### AkShare API特性
- API调用耗时几乎不随请求数据量变化
- 请求1天 vs 请求250天：耗时基本一致
- 概念板块：≈0.6s/板块（无论1天还是250天）
- 行业板块：≈0.3s/板块（无论1天还是250天）

### 重要发现：AkShare V8引擎线程不安全
- AkShare底层用PyExecJS/V8引擎，ThreadPoolExecutor并发会崩溃
- 串行采集是唯一稳定方案，并发只能用run_in_executor串行调度
- 串行采集速度足够：概念376个≈6.6分钟，行业90个≈1.3分钟

### 采集策略变更：概念60天→250天
- 之前概念默认60天，行业默认250天
- 统一改为概念+行业均250天
- API耗时与天数无关，250天不增加任何开销
- 好处：MA20/趋势指标覆盖更全（92.3% vs 68.3%）

### 最终采集结果（250天全量）
- 概念K线: 92184条, 376个板块(372个247天+4个特殊)
- 行业K线: 63479条, 257个板块(全部247天)
- 总K线条数: 155663
- 指标覆盖率: 涨跌幅=99.6%, MA5=98.4%, MA20=92.3%, 趋势=98.4%
- 16个概念无K线源(AkShare API未收录): 已标记kline_name=''

### 性能基准
- 概念376个(250天): 397秒 ≈ 6.6分钟（串行）
- 行业90个(250天): 76秒 ≈ 1.3分钟（串行）
- 总计: 约8分钟/全量

### DB写入优化
- 改为每20个板块批量commit（概念）/每10个（行业）
- 减少DB事务开销
- upsert自动去重：已有数据更新，新数据插入

### 采集脚本改动
- collect_sector_kline.py: 默认天数60→250（概念和行业统一）
- 并发默认3→5（但实际串行，concurrency参数暂不影响）
- 增量逻辑改为每次请求完整250天+upsert（因API耗时不变）
- 删除ThreadPoolExecutor import（改串行）
- 16个无K线源概念kline_name标记为空字符串

## K线采集3模式重构

### 3种采集模式
- **init**: 首次初始化, 请求250天全量, 全部upsert
- **daily**: 每日增量, 请求30天+DB前序数据→合并计算MA/趋势→只upsert DB中没有的新增日期
- **repair**: 补漏修正, 请求250天全量+全量upsert(建议每月1次)

### daily模式核心逻辑
1. AkShare请求30天数据(耗时≈250天一样快)
2. 从DB加载每个板块已有最近30天K线(前序数据)
3. 合并(前序+新采集) → 按日期去重 → 重新计算MA/趋势
4. 只upsert DB中不存在的日期(新增天) → DB写入量极少

### 关键设计决策
- MA5/MA20/trend_state只需要前序数据, 不需要全量250天
- 新增1天数据不会改变已有日期的MA(昨天MA5已固定)
- 只upsert新增日期 = 正确且高效

### DB写入优化
- 从逐条SELECT+UPDATE → 批量INSERT ON CONFLICT DO UPDATE
- 性能: 50条从12ms降到4ms
- 只upsert新增日期: 当天无新增→0条写入

### daily模式性能
- 概念376个: 252秒≈4.2分钟(采集不变, DB写入大幅减少)
- 行业90个: 15秒≈0.25分钟
- 当天无新数据: upsert 0条, 零DB开销
- 有1天新数据: upsert ~633条(376概念+257行业)

### 用法
```bash
python3 scripts/collect_sector_kline.py --mode init      # 首次初始化(250天)
python3 scripts/collect_sector_kline.py --mode daily     # 每日盘后增量(30天)
python3 scripts/collect_sector_kline.py --mode repair    # 补漏修正(250天全量)
```

## K线快速采集(绕过V8瓶颈)

### 根因分析
- AkShare底层: py_mini_racer(V8)获取v_code → requests按年请求同花顺K线
- V8每次调用重建(0.3s/次), 且线程不安全(并发崩溃)
- 但requests部分是线程安全的!

### 解决方案: 预缓存+并发直接请求
1. 预计算v_code(0.1s) + code_map(5s) — 只调一次V8
2. 预缓存概念板块inner_code(并发8, 30s) → 本地JSON缓存(7天有效期, 命中0.1s)
3. ThreadPoolExecutor并发5直接请求同花顺K线API(绕过AkShare封装)
4. 行业板块不需要inner_code, 直接用symbol_code

### 性能对比(376概念+90行业)
| 方案 | 初始化 | 采集 | 总计 |
|------|--------|------|------|
| 原版串行 | - | 5分钟 | **≈5分钟** |
| fast首次(含缓存) | 40秒 | 15秒 | **≈56秒** |
| fast缓存命中 | 6秒 | 15秒 | **≈21秒** |

**14倍提速！**

### 新增文件
- `scripts/collect_sector_kline_fast.py` — 快速采集脚本
- `backend/inner_code_cache.json` — inner_code本地缓存(7天有效期)

### 用法
```bash
python3 scripts/collect_sector_kline_fast.py --mode daily   # 每日盘后(缓存命中≈21秒)
python3 scripts/collect_sector_kline_fast.py --mode init    # 首次初始化
python3 scripts/collect_sector_kline_fast.py --mode repair  # 补漏修正
```

### 关键设计
- 并发度5最优(8会触发同花顺限流)
- 批量大小20(CONCURRENCY×4)
- inner_code缓存7天(板块代码不频繁变)
- 行业不需要inner_code, 初始化仅0.3秒

## 调度器优化: 秒级延时(v2.0)

### 核心优化
1. **并行采集**: 涨停/跌停/炸板 asyncio.gather并行(串行6s→并行2s)
2. **批量DB写入**: INSERT ON CONFLICT DO UPDATE 替代逐条SELECT+UPDATE(5190条≈50ms vs 5s)
3. **缩短采集间隔**: 快频30s→10s, 慢频2min→30s
4. **东财限流降低**: rate_limit 0.3s→0.1s(接口稳定)
5. **注册竞价自动采集**: 9:15-9:25每30秒(之前仅手动API触发)
6. **新增新浪盘中采集**: 每5分钟概念板块实时行情
7. **启动调度器**: main.py lifespan中调用data_scheduler.start()

### 优化后延时对比
| 数据 | 优化前 | 优化后 | 提速 |
|------|--------|--------|------|
| 涨停/跌停/炸板 | ≈36秒(串行) | ≈12秒(并行+10s间隔) | 3x |
| 个股资金流5190只 | ≈130秒 | ≈35秒(批量upsert+30s间隔) | 3.7x |
| 概念资金流 | ≈123秒 | ≈33秒(并行+30s间隔) | 3.7x |
| 竞价全A快照 | 手动触发 | 30秒自动(9:15-9:25) | 自动化 |

### 新增文件/方法
- `_batch_upsert()`: 通用批量upsert方法(ON CONFLICT DO UPDATE)
- `_intraday_sina()`: 新浪概念板块实时行情(5分钟/次)
- `_auction_collect()`: 竞价自动采集(30秒/次, 仅pre_auction时段)

### 调度器启动
- `main.py` lifespan中: `data_scheduler.start()` / `data_scheduler.stop()`
- 9个定时任务自动运行(盘前/竞价/快频/慢频/新浪/盘后/深度/质量)
