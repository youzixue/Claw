# 模拟盘策略 A/B 再评审（2026-08-31）

## 结论

- **账户数据层基本独立**：账户、持仓、手工成交、净值和成交记录均以 `paper_account.id` 隔离，A/B 的资金不会直接互相扣减。
- **执行策略层尚未完全独立**：策略 B 的候选源和止盈止损参数独立，但仍经过策略 A 的若干全局持仓数、日内节奏、午后市场、做 T 和短线卖点规则。
- **两者只有“风格互补”，不是风险对冲**：A 是广谱预案/回踩确认型短线，B 是二板晋级动量型；当前库中 A 的 78 个自动买入事件仅约 5 个与 B 的合格二板信号重合（约 6.4%，按信号日 0～3 天近似匹配）。但两者均为 A 股多头，系统性回撤时仍可能同向亏损。
- **目前不能用实盘样本证明 B 的收益互补**：A 活跃账户已有 193 笔成交，累计收益 -17.84%、最大回撤 -25.28%、成交胜率 49.55%、费用 1439.45；B 账户仍为 0 笔成交、净值 1.0，只有候选过滤日志。
- 当前实现实际已扩展为 A～F 六个账户；本文按需求只重点评审 A/B。源码中的“双策略/五策略/六策略”注释和接口说明需统一。

## 两个策略的职责

| 项目 | 策略 A：default | 策略 B：promotion |
|---|---|---|
| 候选 | 明日预案、盘中异动、回踩/反转等多来源 | `second_board_promotion` 正式调度快照 |
| 入场风格 | 低吸、支撑回收、性价比确认 | 二板晋级概率 + 盘中涨幅/量比确认 |
| 当前仓位口径 | 分层建仓，最多 2 只 | 单层约 20%，配置显示最多 3 只 |
| 当前退出口径 | 紧止损、短线转弱、做 T | 配置目标为止盈 12%、止损 5%、最长 3 天 |
| 组合意义 | 广覆盖、偏低位确认 | 小样本高波动动量补充 |

## 各 Tab 前后端检查

### 账户概览

- 前端向 `/paper/account`、`/paper/nav` 传 `account_name`；后端通过账户主键过滤，数据路径正确。
- 已修复切换账户仍停留旧 Tab、旧请求反向覆盖新账户的问题。
- B 无成交时前端仍可能把成交胜率显示为 `0.0%`，建议按样本数为 0 时显示 `--`。
- 净值线固定使用策略 A 蓝色，建议随策略主题色变化。

### 当前持仓

- `/paper/positions` 使用 `PaperPosition.account_id == account.id`，A/B 持仓隔离正确。
- 新策略首次打开时，旧实现会同时发起多个“获取或创建账户”的 GET；后端没有唯一约束，存在重复活动账户风险。当前库中已经出现 4 个同名 active `reversal` 账户，证明该竞态真实存在（A/B 当前各只有一个）。
- 本次前端改为先完成 `/account` 初始化，再并发读取其他 Tab，降低页面触发该竞态的概率；后端仍应增加唯一约束/幂等 upsert。

### 交易操作

- 买卖请求均携带当前 `account_name`，后端成交落入对应账户。
- 本次增加目标账户快照：请求发出后即使用户切换策略，成功提示仍明确原目标策略，且不会用旧账户完成事件刷新新账户页面。
- 手工交易和自动交易共用同一 `PaperTradeLog` 与账户净值，会污染“纯策略”绩效。若要严谨比较 A/B，应增加 `execution_origin=manual|auto`，并允许绩效口径排除手工校验单。
- 建议提交前二次确认中展示策略名、账户和代码，按钮增加单次提交 loading。

### 自动执行

- 候选源独立：A 走 `_paper_auto_buy_candidates`，B 走 `_promotion_route_buy_candidates`。
- 账户资金、持仓、成交及大部分自动日志按账户 ID 隔离。
- 仍有以下串扰或口径不一致：
  1. B 的状态接口显示最大持仓 3 只，但执行循环仍用全局 `PAPER_AUTO_MAX_POSITIONS=2`（`paper.py:5072`）。
  2. B 的日内买入数、同板块上限、午后/尾盘闸门仍使用 A 的全局规则（`paper.py:4896-5038`）。
  3. 做 T 回补对所有账户运行（`paper.py:4707-4714`）；B 的卖出仍会进入通用短线转弱/部分减仓逻辑，与“单层、三天晋级策略”不完全一致。
  4. 回撤开仓模式是全局配置（`paper.py:895-915`），但 B 状态文案宣称独立 `unlimited`，配置与执行并未真正按账户拆分。
  5. 盘中条件不满足时，账户创建发生在日志写入之后，早退日志未填 `account_id`（`paper.py:4632-4653`）；这些日志会被 A 的历史兼容过滤吸收，B 页面反而看不到自己的早退记录。
  6. 调度器在账户循环外统一捕获异常（`scheduler.py:553-572`）；A 一旦异常，本轮 B 不再执行。
  7. B 的正式快照按上下文可出现同代码重复记录，候选收集没有按代码去重；当前最新二板候选中两个代码各重复两次。应先选最新/最高优先级快照并去重。

### 交易记录

- `/paper/trades` 按账户主键过滤，A/B 记录隔离正确。
- 当前表格未显示手工/自动来源，无法判断绩效由哪类交易产生；建议增加来源列和订单/信号标识。
- 前端旧请求覆盖问题已通过请求代次校验修复，失败请求也不会继续保留另一账户的列表。

## 本次前端修复

1. 切换策略时同步将 `activeTab` 重置为 `account`。
2. 清空旧账户的指标、持仓、净值、日志、评估和成交数据，避免 A 数据短暂显示在 B 标题下。
3. 增加请求代次号；快速切换时忽略旧账户的迟到响应。
4. 先初始化账户，再并发加载其他 Tab，减少首次访问的重复账户创建竞态。
5. 手工买卖、自动演练/执行固定请求发起时的目标账户，成功提示包含策略名。
6. 增加 Playwright 回归测试，故意延迟 A 响应，验证切到 B 后仍保持 B 的账户概览。

## 建议后续修复优先级

### P0（数据正确性）
