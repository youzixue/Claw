## 修复内容

### 1. 已提交预测不再被后处理超时误判为未生成

- `promotion.build_promotion_candidates` 在正式记录 commit 成功之后、健康统计/涨停复盘/页面快照之前，同步向调度器发出提交回执。
- 调度器立即记录当前日期/正式窗口已完成；后处理超时、异常分别标记为 `completed_postprocessing_timeout` / `completed_postprocessing_error`，不再重复追加 pending 批次。
- 重启恢复的只读持久化探针从收盘窗口扩展到所有正式窗口。
- 仍然只检查**最新尝试**：最新批次 pending、模型不匹配、证据无效时，不恢复更早的成功批次，不将已发布等同于路线风控通过。
- 空候选阻断批次和提交失败不发成功回执；原有生成前阻断标记、窗口边界、影子隔离保留。

影响：正式批次发布/恢复状态与运行诊断。没有将页面统计失败变成交易授权，也不修写当天已产生的历史 pending。

### 2. 缩短两处可复现的 SQLite 长写事务

- 模拟盘扫描心跳写入后立即提交，然后读取候选。心跳仅表示“进入扫描”，即使候选读取被取消也不宣称下单或成交。
- 预测生成前的历史学习结果/环境快照准备独立提交，不持有 SQLite 写锁跨越后续慢候选查询和网络补充。
- 临时文件 SQLite 的两个真实会话复现：原路径在候选读取等待期间阻塞另一个 writer，修复后另一个 writer 可正常提交。
- 不在 `_add_auto_log`、NAV UPSERT 或成交事务底层 rollback 后盲重试；未解决的写争用仍抛错，由原账户边界回滚。成交不确定性、锁所有权、原子成交合同不变。

影响：事务持锁时间和扫描心跳持久化时点。**不能据此保证运行库所有写锁都已消失**；上午日志无法反推出每一次锁的实际持有者，仍需部署后观察。

### 3. 竞价采集消除无用历史查询并增加诊断
