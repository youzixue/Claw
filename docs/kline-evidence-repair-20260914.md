# K线历史保留与隔离采证修复（2026-09-14）

## 实际发现与边界

运行源码原有三类风险：THS近期回补按code/date直接覆盖历史OHLC；非交易日/所谓未来fallback自动删除；收盘重试先删除全部同日tencent_close再重建。旧THS首根记录还把开盘价当昨收、涨幅填0。此前已去掉“用今日昨收改写昨日OHLC”，本轮覆盖剩余调度写入路径。

本次仅修改源码和隔离测试，**未在生产执行采集、迁移、后台重启、历史回填或交易**。9/14旧复盘目录/evidence.sqlite保持不动。现存混源/复权/停牌断档不因这些代码变化而变成已修复的历史。

## 新契约

- `backend/app/data/kline_observations.py`：共享写入器只接受指定字段与6位代码，校验OHLC有限正值/包络，量额及可选字段无效值隔离；NULL不变成实测0。非有限观测以显式标签存档，不向SQLite价格列投影。
- 新增 `StockKlineObservation` / `030_kline_observations`：不可变、去重的内容版本目录。候选与原投影分开，保存原值JSON/hash、来源版本、价格基准和处置原因；ORM及SQLite触发器禁止UPDATE/DELETE，迁移不改原价格/预测/交易行。
- **不是逐轮事件历史**：相同内容/处置会去重。recorded_at为录入事务提交前本地时钟，不是供应商时间/物理commit回执；available_at固定NULL，historical_pit_eligible=false。不得把它用于历史PIT特征、正式收益标签或自动晋级。
- 原有历史K线不改不删。现在才收到的历史缺口也仅入隔离目录，不塞回缺少可用时点的StockKline表，让旧决策“看见”后来数据。
- 当日投影须调用方确认权威交易日且与实际录入日一致；默认不授予投影。允许当日腾讯终场固化，但先保留原版本；THS不得盖过tencent_close，spot_fallback不得降级其他来源，SQL再次约束来源优先级。
- 采证与投影共用调用方事务，证据写失败则投影不能提交。未迁移时应失败，不静默回退破坏性upsert。
- 收盘健康保留原分母和原始source_counts，分别报告陈旧终场、非法OHLC、未知来源；不能通过删除坏行、源标签或无效数值提高canonical覆盖。
- `/health.pipeline.kline_observations`为最后一次当前进程采证汇总，含处置数量/问题数量/最多20个例子、实际written和committed；不是全天采集证书。
