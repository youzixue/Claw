**待验证假设：** 在既有首板研究路线内，将“趋势整理后推进”“均线下修复但强开”“水下修复”分层评价，可能比统一套用一种回踩逻辑更合理；尚无多日净收益证据。

- 没有同时验证候选当时入池/授权、振幅位置、盘口失衡、撤单比例、账户额度、真实卖盘。

## 5. 算法、信号、模拟购买的四层差异

### 5.1 各层含义不同，不能混成一个命中率

1. **预测/形态候选**：说明值得观察，排名高不自动获得买入权限；Top12、Top30的目标和覆盖范围也不同。
2. **影子confirmed**：说明该研究路线的确认事件成立；可能没有执行账户连接。
3. **buy_signal**：策略已记录入场信号，但账户资金、持仓数、身份风控等仍需审核。
4. **委托与成交**：需通过提交链路、下一健康行情轮次五档撮合与再校验；信号价不是保证成交价，限价也不是实际成交价。

现有源码依据：
- paper.py:3169—3183、3271—3279：观察候选不能直接升级买单。
- paper.py:3237—3268：A价带只是必要条件，同时保留VWAP与振幅位置。
- strategy_iteration_shadow.py:1550—1614：B2弱开回收；1616—1684：C2低板记忆。
- account_policy.py:1—5、39—53：各账户不共享资金/持仓/自身策略阈值，共享执行约束。
- 完整执行及事件追踪沿用原gate_source_review、opportunity_review与冻结订单。

不能沿用MEMORY中早期“全部B/C等Champion自动暂停”的说法：**今日mainline确实有两笔买入**，应以当日订单和成交为准。

### 5.2 53个买点的成交状态与主要阻断位置

原研究按同事件订单状态优先、再取信号当轮门禁归类；**这不是所有未成交事件的唯一最终原因**。本轮补查后续失效如下。

| 订单结果 / 信号当轮主要阻断 | 事件数 |
|---|---:|
| 已成交 | 10 |
| 日开仓/最大持仓/活动委托预留等容量约束 | 37 |

按事件键追踪后续重评，大为股份先容量不足、后成交已归入10个成交，不能重复记踏空。37是事件数，不是37只互不相同股票，也不全是日额度不足。

**新增纠偏：37个容量归类事件中，24个能按完全相同event_key找到后续skip_terminal。** 其中17个盘口失衡、3个价格/峰值区间失效、4个确认超时；另13个本轮未获得精确event_key后续链接，保留未知，不宣称一直有效。东瑞股份就是先容量受限（log418672），后同事件盘口失衡终止（log419098）。因此不能把37个都解释成“只差放开名额就一定能买”，也不能把后续24次失效再加到53上重复计算。先后相关不证明容量限制导致了后续失效。

复用已核查的事件→订单关联，再按order_id连接fill、按broker_trade_id连接真实模拟账本，未只凭同名/同代码猜配：

## 7. 下一步学习算法：先固定假设，再做多日对照

保持Champion、买卖阈值、仓位和风控冻结。优先复用已有路线/采证，不再新增一个“所有涨停通吃”的平行引擎。

| 优先级 | 可证伪假设 | 对照与验收 |
|---|---|---|
| P0 | 发布/消费耗时改善能减少非策略性信号损失 | 原候选/授权/阈值不变，核对真实completed批次、各阶段耗时、确认提交/消费/风控/成交时钟 |
| P1 | 首板按日K结构×分时路径分层，能改善候选覆盖而不显著增加误报 | 在现有首板研究路线内保留全部候选与失败分母；先看召回/Top-K，再看可成交性，不用9/21收盘信息作特征 |
| P1 | 额度先到先占与分时保留存在可比较差异 | 同一账户、相同总资金/全天额度比较；统计上午被替代样本、午后闲置名额和失败样本，不按今日赢家事后挑名额 |
| P1 | 候选确认到消费长尾缩短，比放宽漂移阈值更稳妥 | 保留原有效期/价差/盘口门；先验证及时消费，失效必须重新确认，不能用历史确认价补成交 |
| P2 | 高标追入和一字无成交不能共用简单收益比较 | 保留锡华等失败样本，评价T+1次日真实可退出、跳空和最大不利波动；6%止损不是当天损失上限 |

信号/交易研究沿用项目最低独立交易日与confirmed样本要求，不能把同股多轮日志当独立样本；达到最低样本也不自动证明正期望。若涉及概率模型晋级，另按技能的walk-forward、至少30日/50正样本/2风格的累计影子门禁、PR-AUC/Brier/ECE/Top-K与人工审批合同执行，两种治理口径不可混用。
