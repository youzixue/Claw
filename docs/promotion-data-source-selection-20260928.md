# 晋级预测去东财：数据源选型（2026-09-28）

## 结论

用户已明确：东财不稳定，弃用。后续方案不再把东财作为主源或故障回退源；历史来源记录保留，不删除、不改写。

**当前项目的低改造成本方案：腾讯盘中行情主链 + 问财低频信息补充 + 经核验的收盘日线/日历。** 不建议把问财网页接口改成唯一主源。

**长期稳定生产方案：优先评估同花顺 iFinD 正式授权接口，确认权限、字段和服务条款后承担关键数据供给。** 不是购买或接入已完成，也不能从产品文档推断实际账号拥有所有字段。

**盘后研究备选：Tushare明确标注同花顺来源的 `limit_list_ths`。** 不把数据来源未核实的其他Tushare接口当成“已去东财”。

本轮只做源码/日志和公开官方文档调研，没有修改生产采集、启停调度、登录账号、购买服务、压力测试或回填历史。当前运行服务尚未完成弃用东财。

## 1. 为什么不选一个源包办所有功能

需要区分三类不同的数据：

1. **即时状态**：最新价、涨跌停价、买卖五档、个股源时间、当前是否封板。
2. **路径与解释**：真实首次/最后封板时间、全天开板次数、连板数、题材原因。
3. **预测真值**：交易日历、正式终场价格、收盘涨停集合、前后交易日连板关系、历史身份及不可变材料。

腾讯有较好的即时字段，但轮询不能看到两帧之间所有开板/回封；问财有路径/解释类信息，但依赖登录、网页协议和结果完整性。盘后榜单在16点发布，不能被用来证明15:10或盘中已经知道该信息。

本次9/28缺池还包含共同本机故障：东财和问财都依赖被删除的临时CA，问财15:20补涨停失败有明确日志。换供应商不能代替修复这一故障。前轮CA持久化补丁仍需单独受控发布验收。

## 2. 候选源比较

| 方案 | 适合承担 | 已知限制 | 决策 |
|---|---|---|---|
| 腾讯 `qt.gtimg.cn` | 盘中报价、涨跌停价、五档盘口、当前涨跌停状态 | 未找到针对该端点的官方API配额/SLA/商业授权承诺；轮询有采样缺口，不提供完整题材与封板事件历史 | 复用现有接入作为本地研究/当前系统过渡主链；不承诺永不失效，长期用途需确认许可与服务保障 |
| 现有 `WencaiStreamSource` | 涨停原因、连续涨停天数、供应商返回的首次封板/开板次数等补充与盘后核对 | 登录Cookie会失效、协议变动、问句列集合不固定；代码保存code_count/row_count不等于所有消费者已校验完整分页 | 保留为低频补充，不置于腾讯逐轮报价的同步关键路径 |
| 同花顺 iFinD QuantAPI | 正式接口的实时行情、日内快照及选股信息，具体范围看账号权限 | 需要Token/授权与额度；本轮未获得测试账号、报价或正式SLA；搜索未确认所有封板细项的具体指标ID | 稳定生产的采购评估首选，先验字段和时点，不直接全量切换 |
| Tushare `limit_list_ths` | 同花顺盘后涨跌停/炸板榜、历史研究与对账 | 官方约16:00更新，不能替代盘中或15:10；有积分权限；仅个人学习研究，商业需联系同花顺授权 | 有权限且用途允许时作为20:00前盘后核对来源 |
| 新浪现有接入 | 板块/成分信息及辅助截面 | 项目里的stock_classify是较慢聚合路径；没有验证为字段齐全、实时独立涨停池 | 不选为本次涨停池主替代 |
| 换AkShare函数名但仍访问东财 | 无 | AkShare是接口封装库，不是独立数据供应商 | 不算去东财，不采用 |

### 官方文档中可核实的内容

- Tushare `limit_list_ths`：同花顺来源，历史从2023-11-01开始，通常每天16点左右增量更新；单次最多4000条；8000积分以上每分钟500次、每天总量不限。**积分不是人民币报价**，实际账号开通条件需要确认。
- 该接口列明 `lu_desc`（涨停原因）、`first_lu_time`（首次涨停时间）、`open_num`（打开次数）等。不能把其“近一年封板率”当成当前交易日零炸板率。
- Tushare明确声明该接口仅供个人学习研究，商业使用需联系同花顺采购。
- iFinD官方文档提供实时行情HTTP入口、Access Token鉴权、数据量/权限说明及行情轮询示例；没有据此验证我们账号的完整涨停路径字段或服务可用性。
- iFinD、问财网页和Tushare同花顺榜共享同花顺上游，不能称为三家相互独立的真值来源；腾讯可作为不同供应商的价格状态对照。

## 3. 本项目可复用的实现

### 腾讯：复用已采行情，禁止再加一套全市场轮询

`backend/app/data/sources/tencent_source.py:410`：
- 100代码一批、最多6并发、复用连接池、短故障有限重试；
- 主要批量行情路径用 `trust_env=False`，避免继承环境代理/CA变量；这不等于关闭TLS校验；
- 已解析涨跌停价、盘口、报价时间。`StockSpot`已存涨跌停价及轮次/源时钟。

建议在原合法报价轮次上产生涨跌停状态投影，不从每次页面GET重新联网、不复制行情调度器。覆盖不全或个股报价过期时记unknown，不凭缺席删除该股。

**不能宣称现在已有完整路径证据**：`quote_round.py`的compact归档列未包含涨跌停价；即使当前StockSpot有该字段，也不能拿今天单行覆盖值反推历史轮次。实现前应核对focus归档等现有载体，按最小增量补齐今后的必要字段与版本，禁止伪造旧帧。

### 问财：已有适配器，不恢复旧pywencai接口

当前用 `WencaiStreamSource`，旧 `PyWencaiSource._query`已经明确报废。调度器3690—3739行的盘后逻辑可新增问财涨停记录，并补东财已有记录的原因；**不是只有东财有记录才允许问财入库**。

但现在还不是盘中自动接管方案。应复用流式适配器，验证：
- 返回日期/日期后缀与目标交易日一致；
- code_count、row_count与实际唯一代码数一致，截断和重复可诊断；
- 每个必需字段存在、单位明确，来源空值不同于真实0；
- 接收/观测时点真实，缓存不跨过调用截止；
- Cookie失效、无result_page、空结果、上游限频分别标记，不让慢请求拖住行情轮次。

频率应在使用许可和实际配额确认后配置，不能套用Tushare的500次/分钟额度到问财网页接口。

## 4. 换源时必须处理的危险字段

| 字段 | 腾讯能提供/推导什么 | 不允许做什么 |
|---|---|---|
| 当前涨停/跌停 | 同股同日有效源报价和涨跌停价比较，结合证券身份/交易状态 | 用统一9.9%阈值覆盖主板、ST、创业板等；陈旧报价当当前 |
| 当前封单金额 | 价格在涨停且买一位于涨停价时，以已校验单位的买一挂单量推导 | 把五档总委买、成交额或“封单占成交比”冒充供应商封板资金 |
| 首次封板时间 | 本系统首次观测到封板的时间 | 将first_observed当成全天真实first_limit；采集晚启动不能补09:25 |
| 炸板次数 | 连续有效帧间已观测到的开板转换次数，最多是观察下界 | 30秒采样没看到开板就填0，或把采样计数直接替代原模型供应商计数 |
| 连板数 | 合格收盘证据+真实交易日历逐日验证连续性 | 历史一天缺数据就断言1板，或跳过缺失日拼接连续 |
| 题材/涨停原因 | 来自已采问财等带时点的解释材料 | 从价格涨停推断原因；未来消息回填旧批次 |
| 收盘涨停标签 | 正式终场且宇宙覆盖可验证的价格状态；与盘后源对账 | 以最后一条普通盘中报价冒充收盘；用复权价与未复权涨停价直接比较 |

**当前代码存在迁移陷阱**：
- `scheduler.py:3989–3995`对缺开板次数/连板数有0/1默认；
- `promotion.py:7489–7493`读取时又用 `or 0 / or 1`；
- 后续首板记忆、封板率、二板评分与交易门使用这些字段。

因此只把腾讯行写进 `LimitUpPool` 会把“未知开板次数”变成“零炸板好板”，可能错误提高评分、绕开原风险判断。必须同步保留字段级unknown和来源质量，让依赖缺失字段的路线保持原本的保守阻断；不能为了换源把风控阈值降低。

这也意味着“报价/涨停名单能继续显示”与“原策略所有路线仍可交易”是两个不同验收条件。

## 5. 去东财不是只删一个类

至少已有以下直接或间接依赖：

- 盘中涨停/跌停/炸板三个池：scheduler + EastMoneySource。
- 二板龙虎榜汇总/席位：promotion.py的EastMoneySource调用。
- 竞价：auction.py中的东财两个域名及f124来源合同。
- 指数历史兜底：index_source.py直接访问东财。
- 大盘资金流：dashboard/EastMoneySource。
- 新闻与个股资料：em.py；名称为ths.py、cls.py的模块仍调用 `stock_individual_info_em`；global_market.py仍调用 `index_global_em`。
- 部分AkShare封装可能隐藏东财上游，需按实际调用和域名审计，而不是只搜索类名。

迁移按依赖分批进行，但最终目标是**正常与备用请求均不触达东财**。未替代的可选增强（例如龙虎榜）明确不可用；若它是某条策略的必要证据，则只阻断对应路线。不能硬删源导致无保护异常，也不能留暗中回退却声称已弃用。

## 6. 推荐实施顺序及验收

1. **信任链修复**：发布已测试的持久CA机制，验证问财请求路径，不靠关闭证书校验。它仍然必要，即便完全停用东财。
2. **数据合同先行**：沿用既有模型、质量服务、轮次/归档，不新增平行涨停榜。补字段级来源、未知、时点、完整性，以及必要ORM迁移/兼容测试。
3. **腾讯状态投影**：复用已有报价轮次；把涨/跌停当前状态、采样路径和正式终场分开。进程重启、跨日、午休、漏帧都保留缺口，不拿旧日池当今天。
4. **问财异步补充**：只补时点合格且字段校验通过的路径/原因材料，失败不拖报价。若采用Tushare，同花顺日榜只参与它实际发布以后的批次。
5. **只读对照验收**：建议至少覆盖5个完整交易日作为工程首轮观察窗口（不是统计稳定性证明），测逐轮覆盖、源报价年龄P95/P99、整轮完成耗时、断线恢复、盘后集合差异、字段缺失与默认值泄漏。以腾讯和已获授权的非东财源做对照，不增加东财请求。
6. **受控切换和清退**：关闭旧主动与备用网络入口，保留历史数据/来源标签和不可变预测；审计域名调用、模型输入、最新批次、各交易账户状态。部署失败时退回安全停止/只读降级，不自动重新启用东财违背用户要求。

上述5日是建议的工程观察期，未开始执行；仍需在上线前明确具体通过阈值，并复用已有行情、预测、交易质量门，不为了通过而放宽。

### 与算法的关系

换源解决的是输入可用性与数据语义，不代表预测命中率提高。新源分布、缺失率、封单/开板口径可能影响首板/二板评分和信号，需用同一冻结候选与历史版本对照。Champion、权重、买点和仓位不在本次选型中调整；封存真值与历史身份治理也不能由新源接入自动豁免。

- iFinD价格、账号权限、封板细项指标、交易所许可和服务SLA未获得，需试用/合同确认。
- Tushare账号是否具备8000积分、实际更新完成时间和全市场范围未实测，不能认为已可用。
- 没有关闭任何运行采集任务。本轮交付是选型和迁移边界，不是“已下线东财”。
