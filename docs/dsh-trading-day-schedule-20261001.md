# Claw 定时研究：按交易日历滚动调度（2026-10-01）

## 实际修改与核验

用户要求修复“只按周一至周五、没有考虑节假日”的两个研究任务。

- 新增并安装项目本地 Host 插件 `@local/claw-trading-schedule`。
- 安装结果：`application=applied`、`warnings=[]`；运行中的插件条目 `include:claw-trading-schedule` 为 `enabled=true / fiberPhase=active`。
- 原生 `schedule_list` 回读：两项均已由 `weekly` 转为 `at`，保留原 ID、任务名称、完整研究提示词和原 Session 绑定。
- 盘前：`schedule-a9739a9f-4a09-483f-aaf6-0352ee1dfa80` → 上海 **2026-10-08 08:00**（UTC `2026-10-08T00:00:00.000Z`）。
- 盘后：`schedule-dc7d5659-6fe2-4656-b9ac-71cf633fea10` → 上海 **2026-10-08 15:30**（UTC `2026-10-08T07:30:00.000Z`）。
- 绑定：`session-124490e5-f1ad-413b-a8b2-de5f960dc3ff`。
- 只追加调度元信息和跨日迟到禁止补做的说明；原 80 次/20 分钟预算、研究截止、报告保存、模式路由与只读工具门禁没有放宽。

## 调度机制

原生 DSH 的 weekly/daily/cron 不支持交易日历。这里不修改原生调度核心，不伪造其规则：

1. 以北京时间寻找**严格未来**的下一次研究时点，逐个自然日读取已存日历；遇到任何日历缺口即停止，而不是推测周末或工作日状态。
2. 当前任务使用原生单次 `at` 记录。原生调度确认投递并将该记录标为 inactive 后，插件使用公开 `schedule.create` 接口，在原 Session 创建下一交易日的任务。
3. `schedule/changed` 事件触发协调，另有每 15 分钟一次的小范围本地日历复核；协调不调用模型、不补采、不启动 Claw 生产调度。
4. 正常状态始终只有两项 active 任务。已投递任务和原生投递凭据保留为 inactive，不自动删除。
5. 用户删除 active 任务、人工修改时间/标题/提示词或发生 CAS 冲突，会停止对应自动管理，不覆盖人工修改或复活已删除任务。
6. 跨 native/task cursor 两处写入使用有界 pending journal：可识别的已提交更新/后继任务能够恢复；提交结果不确定且没有唯一后继时停止，不盲目重试造成重复任务。

**界面说明：**重复方式会显示“单次/固定日期”，不再显示“每周一至周五”；下一次日期是真实已存交易日。投递后由本地插件滚动安排新任务，因此不是仅执行一次就永久结束。后续单次任务会有新的原生 ID；历史已投递 ID 与凭据保留。

## 日历与失败关闭

本次只 SELECT 已有 `trade_calendar`：

- 已存 2026-10-01 至 2026-12-31 共 92 个自然日。
- 2026-10-01 至 10-07 均 closed；10-08、10-09 open；10-10、10-11 closed；下一交易日 10-12。
- 部署时日历投影 SHA256：`347bcde220b911425c32655ec37fb23a64cccee07bf41f0bedd36b115ec58062`。
- 当前覆盖止于 **2026-12-31**。缺少后续日历时不创建新任务；如果原有采集程序以后已经存入可信日历，协调会复用它，不由本插件刷新日历。
- 每次最多读取 371 个自然日、64 KiB 响应，Python 子进程最多 5 秒；SQLite `mode=ro` + `query_only`，不使用 immutable 绕过实时 WAL，也不导入会初始化或补采的业务服务。

另外在真正发起模型请求前重新核验当日已存日历和原 occurrence 日期：休市、未知或跨日迟到的本插件单次提醒将被拒绝。DSH 自身可能在停机恢复时把旧提醒送入 Session inbox；该行为没有冒称已被原生调度消除，但不会把旧日提醒当作今日自然复盘来执行。普通人工消息不拦截，混合批次保留合法消息及其它 pre-step 决策字段。

日历后续修改/删除导致某个已排单次日期不可认证时，不自动删除有历史的任务；标记 blocked 并由投递前门禁拒绝研究执行。这与当前已知国庆假期“不安排休市日期”的正常情况不同。

## 存储与业务影响

- 代码范围仅新插件目录及本说明；未修改交易规则、参数、账户、生产调度器、后端接口、原模式路由或研究保护插件。
- 只写 DSH 原生调度记录和一个有界、原位替换的插件 cursor；cursor 最大 64 KiB，不按轮次追加研究快照。
- 无数据库备份/复制/导出、行情归档复制、回放、结算、下单、推送或 Claw 重启。
- 后继任务投递历史会保留在原生调度存储中；不是无限追加外部证据文件。
- 停用该插件会停止自动滚动，但不会删除已经排好的单次任务；彻底停用研究需同时删除这两项 active 任务。删除后插件不会自动重建。

## 验证结果与限制

- 新增 Node 测试 30 项：国庆、调休周末、上海日界、严格未来时点、缺口、空日历、重复日期、自动滚动、原 ID/绑定/提示词保留、重启幂等、用户删除/编辑、原生投递等待、更新/创建崩溃恢复、CAS 冲突、跨日/休市/未知投递拒绝、只读保护。
- 原研究保护与路由测试 51 项；组合 Node **81 passed**。
- Python 日历读取测试 **3 passed**：小型临时库 SELECT 前后字节一致、不创建缺失数据库、拒绝非法 flag；临时目录自动清理。
- 已核验真实运行 Host 的插件 active 状态、状态 cursor、工具注册和原生两任务目标。
- BrowserSkill 未连接，因此未做 GUI 截图验收，也没有打开替代服务器；实际任务数据已经改变，任务页重新打开/刷新可查看。
- 不在生产任务上人为提前触发；未来真实交易日的自然投递与报告生成仍需前向观察，不把本次测试称为已完成当天研究。
