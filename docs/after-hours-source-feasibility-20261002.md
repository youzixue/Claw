当前来源配置默认 freshness 为15秒；协议允许配置的范围为1–30秒。来源材料每段最多2MiB、持有订单最多2,000、生命周期事件最多10,000；接入评估必须检查这些现有预算，不默认扩大。

交付说明曾提到“可证明保守上界”作为来源审查方向，但**现行源码没有另一套上界证书验收方法**。只有队列总量/上界的产品也不能直接接入当前核；如果只能拿到该类来源，应先另行评估和取得用户确认，不能在本次偷偷改合同。

## 三、来源逐项核查

### 1. 沪市官方 Level-2 / LDDS：可申请部分证据，当前不合格

依据：[官方业务及文档目录](https://www.sseinfo.com/services/assortment/market/)；[正式接口2.0.16，2026-09-18](https://www.sseinfo.com/services/assortment/market/hqywwd/wdzsjk/c/10832622/files/f50ea4de31d843ceb26f5789245c0dfe.pdf)。以下页码为PDF页码。

- 第6–7页：盘后快照 `UA3108 / CategoryID=56`；盘后逐笔成交 `UA3209 / CategoryID=57`；`UA5803 / CategoryID=9` 是竞价逐笔合并数据，不是盘后委托流。盘后成交消息发布时间列为15:05–15:35，不能把15:30后的接收当作窗内证据。
- 第17–18页：盘后快照含 `ClosePx`、`TotalVolumeTrade`、`TotalValueTrade`、`TotalBidQty`、`TotalOfferQty` 和申买/申卖量；订单笔数、订单组、逐笔订单数量及撤单字段被标为“不再适用”。不能把不适用字段填0解释成真实无委托/无撤单。
- 第19–20页：逐笔成交含 `TradeIndex`、`TradeChannel`、`TradeTime`、`TradePrice`、`TradeQty`、`TradeMoney`、`TradeBuyNo`、`TradeSellNo`。其序号按成交通道连续，可检查丢包。
- 第24页：支持盘后成交按通道及序号回补，建议每次不超过1,000条。该回补只解决已发布成交消息的缺包，不会生成未公开的委托或撤单。

**缺口**：未成交订单及其原始申报量/限价/接受序列、盘后撤单、15:05完整队列、队列与成交流之间可重放的完整生命周期。成交中的买卖订单号不能反推出未成交或已撤销而从未成交的订单。快照与逐笔成交属于不同类别，文档明确没有先后次序关系，也不能直接拼成无gap的同一事件链。

产品可通过官方申请或许可转发路径获取；Claw申请主体、认可机房、用途和具体接入资格未确认。购买标准产品仍不能补齐上述字段。

### 2. 深市官方增强行情：许可路径存在，盘后完整流未证实

依据：[官方数据接口目录](https://www.szse.cn/marketServices/technicalservice/interface/index.html)；[Binary行情规范1.17，2025-03-28](https://www.szse.cn/marketServices/technicalservice/interface/P020250328368568358456.pdf)。

- PDF第10–11页：盘后定价快照为频道 `301x`、消息 `303711`；集中竞价逐笔委托/成交为 `300192/300191`，属于另一业务类别。
- 第23、31页：盘后定价行情类别为 `MDStreamID=370`，扩展内容为方向、价格及数量的快照条目。
- 第37、40页：逐笔委托/成交类别表没有列出370。不能借用集中竞价逐笔或盘后定价大宗交易 `300611` 来冒充本次盘后固定价格流。
- 第11页：快照定时发布、不能重传；逐笔消息支持按频道序号检查与恢复，但该能力不能被泛化成盘后订单流已存在。

**缺口**：2026扩围后的盘后逐笔消息定义、完整初始队列、原生订单ID/限价/优先序、撤余量、买卖订单关联及相应补包合同均未确认。2025公开规范是资格不足的证据，不是“市场绝无新来源”的证明。

[官方非展示许可指引](http://www.szsi.cn/cpfw/fwsq/hq/sqlc-3.htm)列出的直接自用申请对象为深沪交易所会员单位、公募基金、中金所会员单位，且要求认可机房、系统方案、验收及审计。Claw申请主体资质没有提供，不能默认可直申。[官方业务介绍](http://www.szsi.cn/cpfw/fwsq/hq/yw-2.htm)还明确：非展示用途须申请许可，由书面认可的接入点提供，不得通过信息商直接接入。许可转发用户的资格和部署位置仍需书面确认。

### 3. 迅投 QMT / XtData：只能待询证，不能凭接口名放行

依据：[迅投官方XtData文档](https://dict.thinktrader.net/nativeApi/xtdata.html)。

- `l2order`：`time/price/volume/entrustNo/entrustType/entrustDirection`。
- `l2transaction`：`tradeIndex/buyNo/sellNo/tradeFlag` 等成交字段。
- `l2orderqueue`：明确为委买委卖一档队列，不是完整市场订单簿。
- 证券状态字典有22/23盘后状态，只证明可以表示盘后状态，不证明逐笔订单流覆盖盘后。
- 需要终端Level-2权限；数据随MiniQmt服务器和权限而变。文档说明Level-2函数没有历史存储、跨交易日清理，不能默认可事后补全完整证据。

**未确认**：盘后新增/撤单覆盖、初始队列、原生通道号与连续事件序号、心跳水位/断线恢复、机器处理及审计留存许可、相应费用和订阅容量。文档可见字段不足以完成当前资格证明。券商自身订单/成交回报只能证明自身订单，也不能替代全部外部前排与对手队列。
