# 延迟卖出审计元数据修复

## 范围

- `reconcile_paper_deferred_orders` 的跨日撤单、策略版本变化/缺失、报价等待、深度等待、风控拒绝和模拟撮合异常六个无成交返回分支，卖出时保留已存的 `paper_deferred_order`。部分/全部成交分支沿用原返回。
- `_reconcile_deferred_order_logs` 对卖出日志使用原委托 `strategy_version`；缺失则明确 `legacy_unversioned`，不以当前账户版本补造历史身份。
- 原始卖点与本轮拦截/成交状态分列。确实没有原候选证据的订单仍是 `legacy_missing`，不回填历史日志、订单或交易。
- Round20首包限定卖出分支；Round22另行补齐买入延期回报，六个无成交返回现在买卖均保留原deferred，日志均使用原订单版本，缺失明确legacy_unversioned。两项都是事实传递，不放宽原下单/撮合门。

## 安全边界

不改原报价、T+1、盘口、风险和旧策略版本检查，不增加提交/撤销/成交调用，不改变原事务提交顺序、原订单限价、数量、费用或幂等键。

原审计测试直接给每个模拟返回都补入 deferred，未覆盖真实生产者六个无成交分支缺字段的问题。新增 `test_paper_deferred_exit_provenance.py` 使用真实生产者进入真实日志适配器，仅报价/风控/券商响应在隔离夹具内替代；覆盖九种分支、买卖两侧、有/无原证据及同轮重入。

## 前向延期执行观察（Round21）

真实延期撮合返回后、普通日志/风险更新结束时，增加独立的 `position_execution_observation / research:position_execution_v1 / execution_frame` 记录。即使成交后持仓已关闭、不再进入后面的 open-position 扫描，也保留本轮订单与成交回报、原策略版本、原卖点及原 position_id（确实缺失则 unknown）。

同步冻结必要叶子，不读写持仓、不多调用行情/风控/券商；物理回报观察时间与原报价轮参数、成交源时间分列。普通业务分支成功之后，Core SAVEPOINT 分块写入现有影子表，由原调用方提交。没有 ORM flush、额外业务提交或失败后回滚整个业务事务；普通异常只告警类型，取消信号仍传播。数据库连接损坏等基础设施故障不能凭保存点承诺业务一定可提交。

批次超过256或成交列表缺失/超过64时不伪装为完整覆盖，不静默截断后声称成功。语义内容相同去重，真实事实变化另记；该路线不是 confirmed 信号，不进入既有策略影子结算，也不产生买点/推送。

## 尚未覆盖

订单 filled 不等于整个持仓清空：前后仓位、全清仓身份、事务提交时点、历史首次可见钟、可卖量/预约量、公司行动/价格基准均不猜造。新事件明确 `replay_ready=false`、`position_fully_closed=null`，尚不能让利润保护回放通过完整性门，也不能据此声称真实卖后收益已验证。无历史补写；部署和真实自然事件验收另行记录。
