# 扫描器资金窗口与连续净流修复（2026-09-14）

## 范围与实际问题
- 父集成文件：`backend/app/signal/anomaly_scanner.py`、`backend/app/signal/capital_anomaly.py`、`backend/app/api/v1/tenbagger.py` 的扫描快照局部；新增 `backend/tests/test_scanner_fund_window_20260914.py`。
- 原全市场默认分支取7自然日内最多5条资金并把NULL变0；单股评分直接取最后5条，会跳过缺失会话或引用未收盘/无来源时钟数据。排行/API修复不能自动覆盖这两个直接入口。
- 原资金检测器把5条中同号的数量称为“连续”，例如“+、−、+、+、+”被当作连续4日；金额也混入了中断之前的流入。
- 本文是源码验收，不是部署或盈利验收；未写生产市场/交易/预测历史，不下单、不推送，不生成真实预测。

## 修复契约
1. 全市场默认与单股路径复用 `load_main_fund_window`：恰好5个本地确认已完成交易会话；源>=15:00，源/接收/原观察时钟合法且不晚于原决策截止；任一缺失、NULL、未来、过期观察或源不支持，历史序列整体为[]。不补日、不用部分和、不制造0。原始有效0与负值保留。
2. `recent_funds_map` 的非空金额列表缺少完整来源证据，只当提示，扫描器从权威loader重新核验；显式空字典仍表示不可用，不回退。当前生产API改为让scanner加载一次，不再提前重复查历史。
3. 快照在任何await前冻结 `fund_decision_at`，传入scanner。即使缓存或DB等待跨15:00也不能让窗口切到当日收盘；快照完成时间仍单独保留。
4. 资金事件追加原截止、实际会话日期、完整性/数量/合计与 `dated_latest_not_pit` 标签。该日最新表仍不是不可变历史PIT台账，不能据此恢复历史信号。
5. 检测器只接收5条有效有限金额，按最新→最旧数当前同向连续run，遇0或反向即停，金额只累计该run；加总溢出不输出无穷资金。连续3/5日、5亿/10亿、各等级评分均维持原值。
6. 历史窗口不可用不会抹去合格当日主力数据；当日资金仍走原来源/时钟/金额、确认与执行门禁，不以历史5天数据替代当前确认。
7. 异动快照版本升为 `v20_fund_window_streak_v1`，不复用旧误报逻辑缓存，不改写旧快照。
