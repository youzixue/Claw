# 晋级预测：快照、性能与算法审查（2026-09-28）

## 结论与边界

本次是 **postmarket 工程审查与研究**，不是盘中推荐或模型晋级。运行证据主要采样于北京时间 2026-09-28 20:24—20:25；截图时点更早，两者不混为同一快照。

问题不能简化成“把概率调高”：

1. **确定的数据故障**：东财涨停采集引用的临时 CA 文件不存在，反复报 TLS CA 路径无效；当天涨停池缺失。收盘批次因此出现新旧证据日不一致并失败。
2. **确定的时效问题**：14:30 窗口有 120 秒超时，收盘又持续重试失败；质量审计与候选构建均有明显开销。
3. **确实没有达到上涨研究目标**：截图近10日原名单186只、122只可评、64只未知，可评子集上涨44.3%。完整上涨率未知，但截图给出的完整名单上界63.4%仍低于80%，不能把差距全归咎于缺失。
4. **算法仍是旧冠军混合模型**：首板概率是静态时序 logit 与路线后验的 75%/25% 混合；上涨概率主要来自路线历史收涨率，不是已部署的独立上涨预测模型。没有证据支持直接换模型或上调概率。

本轮只改 CA 引导及其测试，未修改 Champion、评分/阈值、交易风控、调度器、页面或生产数据库，未训练、回填快照、重启服务或发送交易/推送。工作树已有大量其他未提交改动，全部保留。

## 2. 快照为什么缺失

### 2.1 上游根因：临时CA文件丢失

`logs/backend-uvicorn.log`：

- 420272行（09:30:01）、442820行（14:30:01）及其后连续记录：`stock_zt_pool_em` 失败，`Could not find a suitable TLS CA certificate bundle, invalid path: .../T/claw_ca_bundle.pem`。
- 本轮只读文件存在性检查确认该路径不存在。不能从日志推断是谁或哪个清理任务删除了它。
- `backend/app/core/tls_trust.py` 原实现启动时把 certifi + 已携带中间证书写入固定系统临时文件，并把它设为进程级 `REQUESTS_CA_BUNDLE / SSL_CERT_FILE`；之后只记忆路径。requests每次使用该路径，文件消失可使多个外部数据源同时失败。
- `backend/app/data/sources/eastmoney_source.py:44` 将当日日期传给AkShare；`scheduler.py:2679`采集异常保持旧帧，不凭空造新数据。这次不是先验概率公式造成的缺池。

### 2.2 缺池引出日期冲突，不应绕过校验

- `promotion.py:7343`：盘中二板取前一已完成交易日；收盘取最新涨停池日期。
- 9/28新行情对应首板日期9/28，但涨停池仍是9/24。
- `promotion.py:17744`正式批次时点校验拒绝混合日期。
- 日志455320、455327、455335行：`official snapshot clock does not match ... expected_dates=['2026-09-24', '2026-09-28']`。
- 实际质量模式是monitor：调度器在发现全路线质量阻断后仍进入builder，再被日期门拒绝。不能误称为enforce模式直接提前终止。

**不能用“把日期统一成今天”、旧池冒充新池或关闭质量门来消除告警。** 即使恢复当下采集，也不能伪造缺失历史时点的可见性。

### 2.3 有盘中completed，为何仍报“首板快照缺失”

`promotion.py:2348`的canonical学习批次仅选20:00/15:10收盘快照，明确排除盘中确认；`_build_prediction_snapshot_health:4487`复用此选择器。因此：

- 首板9/28的“缺快照”不等于当天从未有候选或所有盘中预测都失败；
- 盘中尚未到收盘时，泛化的“缺预测快照”容易误导，应分开展示“当前盘中批次状态”和“收盘预测尚未生成”；
- 到本轮20:25，收盘快照确实未成功，已经不是单纯盘中提示文案问题；
- 页面缓存可能保留较早health，不能以缓存卡片代替`/promotion/batch-health`的最新只读诊断。

这是阶段墙钟，包含等待，不是CPU剖析。不能把所有慢归因于计算公式。

20:22:52开始的2000失败尝试23.572秒（quality约9.001秒、candidate约5.378秒）；20:23:31开始的尝试10.369秒。它们均以日期冲突失败，反复执行不会自行修复缺失CA。

### 源码层面待验证的优化

1. **先恢复数据链**：否则算得再快也不能产生合法收盘批次。本轮已准备CA源码修复，尚未部署。
2. **按阶段/依赖失败分类退避**：目前失败后在同窗口不断重新审计与构建。建议复用已存在重试/批次合同，对同一不可恢复源故障减少重算，并在源水位发生变化时恢复；不能假记completed或清除阻断台账。本轮不修改重试阈值。
3. **历史学习/审计移出每次重计算**：`_load_promotion_learning_stats:2017`加载180日结果、canonical选择、解码历史因素并读取方向价链；现有stream/yield改善事件循环公平性，但不等于消除SQL、JSON与重复统计总成本。建议用已冻结数据版本、标签版本和成熟结果水位作为缓存键做等价复用，明确失效条件，禁止跨as-of缓存未来信息。
4. **请求分开完成、分开展示**：`frontend/src/views/promotion/Index.vue:2225`用Promise.allSettled等待四接口全部结束后才赋值；慢复盘会拖住本来已完成的顶部卡片。可独立更新各模块，不必改变预测口径。
5. **热路径按需列投影与分期数据加载**：snapshot health读取大ORM历史对象；候选与学习复盘都做大量数据工作。必须先用冻结基线比较候选、概率、顺序、门禁完整输出相等，再测P50/P95/P99与事件循环延迟，不能只报某个子步骤提速。

本轮没有上线上述性能策略，也没有声称端到端响应已经改善。

## 4. 算法审查

### 首板事件概率

`promotion.py:2657–2799`：

`P(first_board) = 0.75 × sigmoid(固定时序线性项) + 0.25 × 路线后验概率`。

固定时序系数的源码声明训练窗口为2026-06-09..08-10、留出08-12..08-27。输入包括涨停记忆、板前试探、板块涨停增量、上下沿距离、平台/挤压/量窒息等；路线校准使用Beta先验及有界残差。形态分不再直接等于70%—90%事件概率，这是合理的防虚高措施。

局限：
- 固定系数训练窗口短，不能据此证明对9月各风格仍适用；
- 候选召回先限定了上限，纯重新排序无法找回未入池股票；
- 不同路线、小样本状态桶的后验及低基准率会压低预测值，概率低本身并不是bug；
- 首板目标与普通收涨目标不同，不能把“涨停因子有效”推导为“上涨预测有效”。

### 上涨方向概率

`promotion.py:2815–2875`：优先用路线全池历史收涨后验，再加很小个股残差和目标专用logit增量；样本缺失回中性先验，不是新监督方向模型。因此同路线分数集中、个股区分力有限是合理怀疑，**不是已证实唯一失效原因**。

`promotion/direction_research.py`已有独立方向研究榜，但只是按现有direction_probability排序；`promotion/modeling/direction.py`已有独立logit/walk-forward研究入口，未因代码存在就成为生产模型。

## 5. 可证伪的后续实验，不日更生产参数

| 优先级 | 单一假设 | 复用实现与验收 |
|---|---|---|
| P0 数据 | 修复CA后合法当日涨停池和新收盘快照能恢复 | 采集源健康、当日池水位、批次日期一致、最新正式run完成且质量门通过；只产生真实新批次，不补旧时点 |
| P1 召回 | 趋势推进/修复/整理分层宽召回能增加真实首板覆盖 | 固定同日可见候选，保留原Top12与宽Top30；比较全市场池召回及固定K精度，不以扩大名单假装排序改善 |
| P2 方向排序 | 独立T+1收涨logit优于路线均值 | 复用direction.py与train_promotion_challenger.py的next_day_close_up目标，标签严格为封存T+1收盘/前收盘；不以涨停/盘中最高价替代 |
| P3 校准 | 时间隔离的Platt校准可改善概率可信度 | 训练→校准→验证按交易日严格分离，比较AP、Brier、ECE、TopK及各市场风格；不修改原门槛以“通过” |
| P4 性能 | 历史证据统计可按版本复用且减少重复IO | 冻结相同输入，候选/概率/排序/风控输出完全一致，记录端到端耗时及事件循环延迟；不以延长超时掩盖问题 |

正式方向研究要求至少30独立OOS日、每天固定12只、500次整交易日bootstrap、单侧95%下界≥80%、无遗漏批次且原离线质量门全通过。80%只是研究目标，不是承诺。

**当前研究材料还不具备自动晋级条件**：`daily_materials.py`默认审定解析器集合为空；`identity_evidence.py:59`默认`no_reviewed_identity_source_v1`；ledger_dataset另要求封存结局、身份和整批完整性。恢复业务行情不等于补出了历史首知或合格训练材料。应先打通真实源协议与不可变材料生产，不要绕过这些门或用零填缺失特征。
