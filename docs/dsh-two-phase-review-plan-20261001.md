# DSH 盘后复盘与盘前预案：调整与缺口方案

日期：2026-10-01（Asia/Shanghai）。本文件保留最初源码审查与建议，不是当前部署状态或策略盈利证明。
后续实施与任务验收以[实施记录](<dsh-two-phase-review-implementation-20261001.md>)为准；下文“本轮未修改/未创建”指方案审查轮次。

## 1. 总体判断

建议使用两个重复任务，共用冻结证据包和研究台账：

- 盘后任务：十二账户交易绩效、逐股执行/通知归因、全市场走势学习、优化必要性判断。
- 盘前任务：上一交易日复盘 + 休市期间/隔夜新增消息与外盘事实 + 有条件的开盘预案。

Claw 继续负责确定性采集、核算、结算与冻结；DSH 负责证据读取、解释、研究编排与建议。任务不得替代原有交易调度。研究学习不等于每天修改生产算法。

## 2. 推荐触发时间与就绪条件

| 任务 | 建议时间 | 就绪条件 |
| --- | --- | --- |
| 盘后全策略复盘 | 每个交易日 21:45 | 当日已结算结果、盘后快照、研究归档可读，收盘日K覆盖可核验；缺项须标记部分完成或失败 |
| 盘前综合预案 | 每个交易日 08:55 | 目标日确为交易日，上一有效交易日证据一致，盘前快照及截止时点以前的隔夜事实可读 |

两任务显式绑定 Asia/Shanghai，并在执行时读取可信交易日历，不能只判断周一至周五。日历未知不得自动认为开市。盘前还应比较日历预期的上一交易日与实际K线/报告日期：库内最近日期可能因停更而更早，不能无声退到旧数据。

现Claw scheduler虽然声明Shanghai，但多处传入的CronTrigger未显式带timezone，实际还受OS时区影响；生产触发器时区与next_run_time未实测。上线时应一起核验，而非仅看调度器顶层配置。

时间选择依据：[现有调度](<../backend/app/data/scheduler.py#L940-L1000>)包含20:35盘后/08:45盘前冻结；[研究归档](<../backend/app/data/scheduler.py#L1099-L1106>)在15:50/20:45；[日K维护](<../backend/app/data/scheduler.py#L1063-L1086>)还有21:00兜底和21:20修补。源码有调度不等于本次线上均成功完成，必须检查实际水位和产物。

21:45报告必须区分20:30冻结快照与后来修补的K线版本，不把后来的内容无声拼回原快照。08:55预案也要明确自己的新闻/行情截止时点，不能把08:45以后新增材料标为08:45已知。

若错过盘前时限，不使用开盘后的信息补造盘前预案。DSH停机/电脑休眠不能保证准时执行；恢复后要区分补交报告和历史当时可见的预案。

## 3. 盘后任务固定工作内容

### 3.1 十二账户账务与买卖

A–F、A2–F2逐户列出：实际委托、成交、费用、当日已实现收益、未闭合持仓浮盈亏、完整交易周期、退出原因、版本与排除量。C3单列研究事件，不作为第十三个执行账户，也不合并成共享资金池。

当前版本绩效、旧/跨版本成交事实、控制/探针样本分开；不能为了只报当前协议而漏报真实历史账事实。卖出一次不一定是完整周期，未闭合浮盈不能混入已实现胜率，参考价格标签不是实际可执行净收益。

### 3.2 全市场研究宇宙

全量结构化覆盖当日上涨与涨停股，同时保留平/跌、炸板、相同形态失败、未成交及拦截对照。分别报告全市场、当时可交易宇宙、策略观察宇宙与实际候选池分母。

近几日日K与分时特征由确定性代码批量计算；DSH做分组解释，并逐笔/逐股详查全部交易及明确异常案例。不是每天让模型逐张截图浏览数千股，也不能只精选赢家。任何截断、缺K线、未评价或历史身份未知都要保留数量与股票清单引用。

### 3.3 逐股证据链

串联：首次可见行情/候选 → 形态观察 → 确认/重置 → 风控/资金/容量 → 委托 → 成交 → 可卖 → 退出；通知另串联信号 → 入队 → 尝试发送 → 通道回执。

按问题分类：

- 未推送：没形成信号、仅研究、冷却/限频/过期、入队/发送失败或证据未知。
- 踏空：未采/未扫、召回/排名、未确认、风控、容量或不可成交；合理风险排除不自动当作错误。
- 追高：首个当时可验证买点与实际确认/执行时点比较，区分数据延迟、策略确认与执行排队，不用当天最低价倒推应买。
- 被套：分开买入条件、后续走势、T+1约束与退出执行。亏损本身不能证明代码错误。
- 卖飞/退出迟：复用完整周期与退出后归档，缺终场健康、缺盘口可成交性时不给反事实可执行利润。

没有逐股日志只能写unknown；不能把账户汇总原因贴给每只上涨股。通道sent不证明用户收到，旧未采的接收/发送价格不能回填。

### 3.4 优化结论

每个问题归入：保持不变 / 数据采证修复 / 工程修复 / 策略实验 / 证据不足。

工程故障要求可复现、局部修复和等价性回归；策略/阈值变化要求冻结基线、时间外检验、同候选失败对照、费用与不可成交约束、尾部风险及现有策略门禁。不为了增加推送或成交数量而放宽风控。

## 4. 盘前任务固定工作内容

1. 解析目标交易日、上一有效交易日、盘后报告ID与证据版本；不是简单取昨天。
2. 新闻窗口覆盖上一交易日收盘至本次截止，包括周末和长假，不限于最近20小时。保留旧事件持续影响和真正新增信息的区别。
3. 外盘区分美国常规盘、盘后、股指期货、相关行业/中概、A50、汇率、利率与商品。每项保存源市场、session、源时区、源时间、接收/可用时间、交易日和质量；不把指数日线当美股期货或盘后报价。
4. 新闻复用PIT原文/分析版本；公布时间、首次接收、内容可用与分析可用时间都不能穿越截止。原文事实、行业映射推断和模型情绪分开；没有新闻样本不等于确认无重要新闻。
5. 结合上一日风格、持仓风险与研究结论，输出高开/平开/低开情景、关注板块与观察池、既有策略确认条件、失效条件、风险与缺失源。外盘上涨不直接等于A股某股必须上涨。
6. 盘前预案冻结保存；后续竞价确认或新闻变化另追加版本，不能覆盖原预案。下一次盘后复盘对照原预案与实际开盘，形成反馈闭环。

美国夏令/标准时间必须按日期与交易场所处理。在采用16:00–20:00 ET盘后时段的场所，标准时间期间北京时间08:55仍可能未结束，应标为进行中而非终值。官方依据：[NYSE交易时段](https://beta.nyse.com/trade/trading-information)、[NIST夏令时规则](https://www.nist.gov/pml/time-and-frequency-division/popular-links/daylight-saving-time-dst)。源报价时间字符串的时区本身仍需验证，不能直接套偏移。

## 6. 只读边界必须先收紧

现14 MCP工具已注册和部分实际读取成功，但这不证明所有14条调用链严格无写入。五条模型记录链（prediction_runs、training_runs、shadow_runs、shadow_evaluations、deployments）会调用[建表初始化](<../backend/app/promotion/ledger.py#L153-L172>)；表存在时通常仅检查，缺表时可尝试DDL。GET白名单与readOnlyHint不是数据库写保护。

新增和修正读取应使用独立无autoflush、query_only/只读事务，缺表返回unavailable，不能ensure/init、建账户、重估NAV、补采、扫描、结算、出版、重试发送或刷新动态池。现账户/通知/新闻/日历/预案GET应逐条审查，不按名字代理。

测试要覆盖真实路由依赖链的禁止DDL/DML，而不只mock HTTP或检查annotations。现[MCP测试](<../backend/tests/test_ashare_review_mcp.py#L71-L94>)验证调用映射时fake_get，不覆盖后端缺表副作用。

- [ashare-daily-review](<../.dsh/skills/ashare-daily-review/SKILL.md>)：保留市场/预测职责，补自动化输入manifest、阶段就绪、报告版本与前一预案反馈。
- [claw-paper-review](<../.dsh/skills/claw-paper-review/SKILL.md>)：扩展逐笔/逐周期/浮盈亏、全市场胜败对照、逐股执行与通知时间线、未评价覆盖与优化分流。
- 盘前规范：先扩展ashare-daily-review的独立盘前章节，负责上一有效交易日复盘 + 隔夜事实 + 情景预案；篇幅增大后可拆成薄编排Skill claw-premarket-plan，仍复用同一证据模块，不另造预案或交易引擎。不能直接以现明日预案GET取代纯读冻结证据。
- [claw-strategy-experiment](<../.dsh/skills/claw-strategy-experiment/SKILL.md>)：补可累计研究队列、假设去重、滚动证据、基线与停止条件；不机械套用单一模型晋级样本门槛到所有策略。
- [claw-safe-feature-iteration](<../.dsh/skills/claw-safe-feature-iteration/SKILL.md>)：补工程修复/策略变化分流、隔离实现与测试、部署审批边界。

初期保留并扩展现有四个项目Skill即可；盘前编排Skill可以后续按篇幅拆分，不是必须新装的插件，也不能替代数据缺口。

插件方面优先扩展现claw_ashare的证据读取：交易日历/就绪manifest、已归档研究、执行账、决策轨迹、历史通知、价格/市场宇宙、PIT新闻、隔夜冻结上下文。具体工具名与schema需在实现前审查确定。

BrowserSkill只作图形与页面验收，不是主证据源；连接未完成不妨碍MCP研究。Context7用于开发文档，Excel用于展示，不补采证缺口，均可随后接入。

## 8. 自动化工程与代码优化权限

任务需持久化输入指纹、报告版本、证据ID/哈希、失败/缺失清单与改进工单；盘前按ID读取盘后结论，不依赖聊天摘要。幂等键包含任务、交易日、输入/提示词版本；同一输入不重复报告或推送，修订另保存。设置重入锁、有限重试、超时、数据就绪截止与字节/股票覆盖预算，保留上一份成功产物。仅保存有界报告与证据引用，不每日复制整库，也不擅自清理原始证据。

当前会话权限宽，不能把Skill中的禁止项当实际权限沙箱。无人值守研究应使用受限工具/权限，仅暴露审定读口与研究报告输出；自动改代码、重启或部署另走开发审批流程。

可自动做：归因、优化必要性分类、创建待审研究/工程工单。以后明确授权可在隔离分支生成补丁并测试；生产买卖规则、参数、模型激活与服务部署仍需针对具体动作批准。

## 9. 推荐实施顺序与验收

1. 修正MCP的缺表DDL边界；定位影子采集停止、外盘源与盘前截止问题。
2. 复用已有研究层，补纯读的交易/通知/价格/日历/新闻/隔夜reader与输入manifest，不新造账本或策略。
3. 调整四个Skill的盘前/盘后章节与共享报告契约；仅在需要时拆分薄盘前编排Skill。
4. 先进行两类任务单次受控验收，再创建重复任务，避免与20:40旧GPT报告入口重复运行。

验收覆盖：正常交易日、长假、日历未知、收盘/新闻/行情缺失、采样缺帧、复权切换、新闻晚采/修订/分析晚完成、美国DST/休市、零交易/亏损/分批退出/T+1、重复触发/崩溃恢复、开盘后补触发、接口缺表及禁止DDL/DML。任务已显示在列表、Skill已加载、报告标built都不是完整验收证据。

本轮仅新增这份方案文档，没有创建任务或进行业务修改。
