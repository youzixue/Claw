## 数据合同

### 腾讯：可核验的价格状态

纯解析器 `backend/app/data/limit_pool_source.py`：

- 逐股真实 source_quote_at、received_at、observed_at 必须同日且有序。
- 正价格、昨收、成交量、high/low、明确上下限，检查有限值与 OHLC/上下限一致性。
- 不按10%猜涨跌停价，不把零成交、停牌快照或缺失源时钟认证为当前状态。
- 源报价不早于09:30；盘中有效年龄默认120秒。同日真实15:00及以后报价可以作为当晚终场状态，14:59旧报价不能冒充收盘。
- 重复代码整体拒绝；部分批次只清退逐股核验通过的旧状态，缺失代码不作负样本、不清空全市场。
- 当前价格等于上限 => up；等于下限 => down；日高触及上限且现价低于上限 => broken。
- high触板只能证明当日曾触板，不能证明首次封板时间、开板次数或封板持续时间。
- break_count、consecutive_days、首次时间、封单额未知即 SQL NULL；显式绑定 NULL，不让 ORM 的旧默认0/1填入。
- 状态写入与 StockSpot/QuoteRound 同事务；批量操作而非每股查写。
- StockSpot 已验证逐股水位不能被回退/无时钟报价覆盖，即使对应股票已经退出全部池，旧缓存也不能复活旧涨停。
- QuoteRound.component_watermarks_json 保存 limit_pool 覆盖、终场覆盖、拒绝数和范围。归档新增真实上下限列，旧档缺列不回填。

### 问财：有界、带日期的元数据补充

- 查询明确当日；只识别该日 [YYYYMMDD] 列：连续涨停天数、涨停开板次数、首次涨停时间、涨停原因类别/涨停原因、涨停封单额。
- 保留真实0开板；缺失、NaN/Inf、错日、重复代码、返回条数小于声明 code_count/row_count 时拒绝/保留未知。
- 明确单位的元/万/亿数值列才换算；不猜复杂单位字符串。
- 只补已有腾讯认证涨停行，不单独插入涨停股，不修改腾讯状态时钟，不因问财空结果删除市场。
- 首次涨停时间不得晚于请求开始，且须落在09:25–15:00。
- HTTP期间不持有DB事务；若等待中腾讯状态源时钟已晚于请求开始，跳过该股补充，等下一轮，避免较早答案覆盖较新状态。
- 字段证据单独保存请求时间、真实响应完成时间、已知字段、供应商时间精度。没有供应商精确时钟时明确为 trade_date / provider_timestamp=null。
- 盘中元数据默认300秒后失效，后续状态投影清空旧字段；只有实际收盘后获得的同日元数据可供晚间继续使用。
- 超时默认45秒；shield保留唯一在途SSE请求，不在每次超时后另开线程。退出任务时清理拥有的任务。
- 盘后补充和收盘固化复用同一条补充函数，失败不重启东财。

## 消费与交易影响

- 新源缺关键字段或源时点陈旧的行不进晋级分类/排名；不按首板或零炸板享受概率加分。
- 最近涨停记忆中缺板数/开板数/封单额的记录不获得质量加分；原有有值样本、查询顺序、分批游标/取消合同保留。
- 预测结算遇到板数未知仍保持 pending，不误标首板成功或失败。
- 质量门新增真实覆盖/终场/元数据完整性证据，不再以“有一条涨停”证明新源完整。
- 数据不完整时情绪质量降级；晋级 board-height 返回 null 指标与 source_health。前端显示 -- 和待补/陈旧提示，不显示虚假的0市场。
- 风控阈值、仓位、止损止盈、成交/订单链和 Champion 权重未改。
- **候选、信号、复盘标签和页面展示可能变化**：缺失字段时更保守，腾讯状态与旧池口径可能有差异。接入新源不等于上涨率/首板命中率提高。
