## 二、漏斗怎么读，避免再次误诊

请求中的七层全部保留，但**不是强行凑出一组单调递减数字**：

1. **扫描**：进入扫描heartbeat及当时buy_attempt_allowed。进入不代表所有候选扫描完成；完成总量未完整落库则unknown。
2. **数据合格**：实际消费批次的路线门与逐股data_gate。缺正向回执时不能用“扫描数－拒绝日志数”推合格数，一轮可能有多条日志。
3. **候选**：B/C/D选中正式run中的路线库存；D2各route_version结构池；E2/F现存逐股观察并集。不同分母不能相除；排名、actionable、概率通过是并列条件，不是天然嵌套。
4. **模式**：原版本真实首个拒绝条件，以及是否到达报价确认。数据缺失与模式不符分开；同股当日可能失败后恢复。
5. **确认**：quote_ready只证明报价路径，buy_signal是去重的确认事件记录，仍不等于完整独立机会总数。D2单独按confirmed事件；不借用B2/C2来代表B/C。
6. **委托**：不同原buy order_id，取消、风险拦截、待成交分别保留。E2重复同股重新排队不能当不同股票。
7. **成交**：真实buy fills关联到原订单，分片数量校验。无订单只证明没提交，不能倒推上游无机会。

统一表中列名明确“observed/log_rows/codes/unknown”；协议前的零条记录不解释成零个市场机会。完整历史数据合格总量和独立确认机会总量仍有证据缺口，已经显式保留，没有用猜数填满。

## 三、最重要的具体证据

### D/D2：先修可消费竞价源，别先改买点阈值
- 9/28 D进入466次，437次允许尝试，其中435条明确竞价数据门、1条批次blocked、1条可见时点失败；没有买委托。
- 9/24现存正量终场源钟：2617股仅1帧、369股2帧；9/28 2989股均只有1个不同终场源时刻。这个结构统计不是历史PIT重放，但与原正式run冻结多帧门失败一致。
- D2 9/28有56股结构记录，同时56股证据阻断，450条市场覆盖告警是整日反复观察，不是450个新竞价机会。末次event1409147的prior_structure明确raw_price_path_codes=56、verified_path_codes=0。
- D2早/中/末路径与D双时点门不是同一需求；普通盘中开盘价或累计成交量不能伪装早期竞价。9/4、9/7的D2 coverage_blocked实际是同帧市场行情覆盖不足，并非全部指竞价；D的月初门也不是后期95%/双帧合同，必须按原版本解释。
- **优先验证**：原源适配和采集过程能否自然产出合法源钟、量价语义、单位及独立多帧；若上游本身不提供，只加轮询不会修好。合法证据未齐前，后续模式有效性仍不可判。

### B/C：上游供给、资格、模式、确认分别有损耗
- B 9/8两股曾报价确认，但77条后续质量门拒绝、0单；这是“有信号但后续被挡”，不是没有模式。该历史条件与持续实验是否本应仅标记情绪需结合当时合同分层，不能据当前代码追认。
- B 9/10—16多日路线库存非空，但actionable与概率>=0.25交集为空。补查冻结JSON后，9/15 run91明确：池43、非观察资格6、actionable5、概率达标1，但最终交集仍0——不是概率全部低，而是条件落在不同记录上。9/10、11、14、16、22首末样本有概率达标0，仅认证所引用批次，不外推所有中间轮；9/23、28另有原文互证。
- B 9/17同股先因低于VWAP撤单、后新单成交；9/21实际“追高”拒绝，9/24实际“低开”拒绝。不同日期不能套一个根因。
- C 9/18路线池最多50、具交易资格43、排名资格49，但当时actionable/可消费排名为0；证明“有原池不等于有执行入口”。9/23记录已出现冻结资格+独立确认分支，不能把旧入口问题说成当前仍完全没修。
- C 9/21有3只确认记录，2单2成，另一只被日开2只额度约束；9/22—24还有成员/催化等独立确认不足，9/24历史独立确认出现0.020概率下限。配额不是应自动去掉的故障。
- **优先验证**：在原消费run与原冻结候选上区分生成屏障、数据失败、资格/全局榜单截断、独立确认和容量；只比较同候选、当时可见的改法，不调月内阈值凑交易。

### E2：14笔到期实际是同一天、同一股反复排队
- 9/24的16单全部未成：601811在20.35反复排队14次，到期14次；000910两次原价格条件失效。排队前方约8.68万—10.59万手，不能当有卖盘可成交。
- 9/23同一001216两次回撤失效撤单，第三笔重新确认后成交；这是3单1成，不是3只股票。
- 9/8、9/9虽有模式确认，日开1只上限还分别形成334/156条重复拦截；不会因此增加独立机会数。
- **优先验证**：原确认到期后，持续封板是否无新的模式路径就被重武装；区分真正的新信号与重复排队，保留TTL、队列穿透、不可成交约束。不先延长TTL或放开日限。
- 封单真实不足、VWAP/回撤失败被旧综合摘要打成data_quality，属于归因污染，不能以此误诊数据源“断供”；明确quote_missing则另记，不能假设停牌与数据故障相同。

### F：历史形态稀少，实时窄窗口确实可能错过持续确认
- 9/16—24的逐股记录主要停在未断板、前连板不足、无更早封板；9/16之前缺逐股细分，不拿新版代码倒填。
- 9/28观察53股：48只历史形态拒绝、3只历史数据缺口，2只进入实时条件。603230持续低于VWAP；001317在09:47:23只有1帧/0秒，下一轮09:47:53即涨幅超入口上限，未满足原2帧/60秒。
- **优先验证**：“前日已封板反包→次日低涨幅承接”的模式，与持续确认所需窗口是否匹配。保留足够样本、完整路径、费用/T+1/不可成交约束后离线比较，不用事后涨幅证明应该提前买。

## 四、修复优先级与验收，不把审计当修复

|优先级|对象|最小动作方向|什么才算通过|
|---|---|---|---|
|P0|D/D2|原竞价源合法性、多源钟/时段覆盖及消费者合同适配|自然交易日原始帧可追溯，D/D2各自原门真的通过；非制造时间戳/降低覆盖门|
|P0|B/C|正式批次可见/完成供给，逐路线质量与候选资格消费者一致性|同一冻结候选能逐步解释去哪层；已修分支与未修分支按版本分开，不能仅API返回成功|
|P1|E2|同股同模式重复到期重入的状态机与可成交性|原TTL不续期；新入口要有新证据；重复订单下降不以偷偷删失败分母换取|
|P1|F|模式成立后有效价格窗口与持续确认的冲突验证|同候选同时间隔离的离线/影子对照，计费用、T+1、涨跌停与无深度；不能仅提高交易次数|
|并行纠正|六路|真实缺数据、策略失败、容量与运行状态分层|旧账不重写，研究统计不把no_candidate/data_quality旧标题当事实|

本次只完成这份只读漏斗定位，**不是上述修复已实施或已上线**。提高频率不是成功标准，长期净期望也不能由这些漏斗直接证明。
