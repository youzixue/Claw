## 根因与最小改动

原 watchdog 在持仓风控与主账户/E2扫描完成后直接设置 last_processed_round。A2/B2/C2/D2/F2 的确认执行位于 `_process_quote_round_shadow`，却未被 watchdog 调用；随后主事件消费者将该轮视为重复，仅补 A2 证据，不再执行次账户。

修复：

1. 在同一个 dispatch 锁内沿用原顺序：完整持仓风控 → 主账户/E2 → 现有影子及次账户确认执行入口 → 标记派发轮次完成。不创建平行策略或直接下单入口。
2. watchdog 增加轮次 ID 去重。即使时间去抖已过，同轮也只能补 A2 证据，不能重复派发交易或伪造新成功时钟。
3. 持仓风控失败时与主事件消费者保持一致，只调用 `execute_challengers=False` 的采证入口，然后保留失败，不标记完成。
4. 无新鲜完整报价仍仅清理过期买单；取消继续传播且释放锁/重入标记。原执行层仍验证事件可见时点、有效期、价格、盘口、版本、账户额度与提交风控。

影响：修复故障接管时的模拟账户执行覆盖，可能减少技术性错过；不意味着每条确认都会下单或成交。E2属于已有主扫描循环，本次没有把它重复接入次账户入口。
