# 安全迭代

AGENTS.md 是项目规则，不被此 Skill 替代。先区分“研究结论”“功能修改”“参数/策略变更”“部署操作”，
研究请求不自动授权后三者。

## 定时研究与人工工程分离

带 CLAW_AUTOMATION_V1 标记的回合只能读已审计证据、保存研究报告与待审工作项，
不能调用此 Skill 执行代码修改。人工明确选定某个工作项后才进入以下工程流程。
部署状态以运行证据验证；源码修复、Skill 加载或测试通过不能替代运行服务部署。

## 修改前

1. 检查工作树及相关文件现状，记录本任务文件范围；识别用户并行改动，不清理、回滚或覆盖。
2. 阅读相关源码、.workbuddy/memory/MEMORY.md 与对应业务文档；定位现有 service/engine/model/API/composable，
   不为单次需求创建平行交易逻辑。
3. 写清验收条件、输入输出/单位/时钟、空值与异常语义及可能影响：信号、订单、持仓、收益、回撤、风控或展示。
   涉及收益假设先使用 claw-strategy-experiment，不把一次上涨复盘直接转为生产阈值。
4. 修改共享接口、scheduler、settings、ORM、router 或交易核心前缩小补丁；
   如存在并行冲突，说明合并顺序，不擅自重构。

## 实现边界

- 交易依旧通过 trading/service.py 和 risk/engine.py；策略、订单、风控、成交与持仓边界保持清晰。
- 数据源字段、费用、指标公式和交易日遵守现有口径；未知或异常交易输入默认降级/拦截。
- 大文件定位局部函数小步修改；前后端字段/单位/错误契约一起检查，不破坏既有 Tab、筛选、导出、空态。
- 新 ORM 字段考虑 Alembic；不把开发库自动补列当正式迁移，不未经批准对现用库执行 DDL。
- 不在日志、截图、报告里展示凭据。没有具体授权，不重启 Claw、跑写库回放、补单、发推送或做模型晋级。

## 验证

1. 检查测试入口确实隔离数据库、任务调度、外部行情、券商和推送；不得把测试跑到现用交易库。
2. 后端运行对应 pytest；涉及交易/日期/因子/风控等补边界测试：正常、空/缺失、异常、不可成交及 T+1。
3. 前端改动至少运行现有 npm run build；重要交互用 BrowserSkill/Playwright 做受控验收。
   browser-skill 需先加载，浏览器扩展连通才可使用；未连通不能宣称已验收。
4. 浏览器验证前审查页面初始化请求；GET 也可能创建/刷新账户。默认用测试环境或已审查只读页面，
   不点击买卖、自动开关、重算、模型审批等按钮，不以默认共享浏览器会话为安全隔离。
5. 核对本任务 diff，不改其他人的文件；测试失败、环境阻断或缺少实测必须如实列出，不能用 mock 冒充真实接口。
   MCP 只读工具和浏览器测试都不替代确定性交易回归。

## 交付

简述修改、原因、影响模块/交易结果类别、测试命令和结果、剩余风险、并行冲突。
把“代码验证通过”与“运行中服务已部署”分开。部署/重启/迁移/策略激活仅在用户明确批准具体操作后执行；
注明备份、回滚和部署后验证，不因 Skill 已加载而取得写交易数据或扩大风险的权限。
